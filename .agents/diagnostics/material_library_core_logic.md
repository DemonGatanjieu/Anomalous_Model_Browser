# 素材库核心逻辑与验收基线

**状态**：MVP 已实现（2026-09-03）

**范围**：生成图快照、完整工作流打开、同类型节点参数应用

**关联模块**：`api/materials.py`、`web/modules/ui_materials.js`、`web/modules/ui_recipe_detail.js`、`web/modules/ui_doctor.js`

---

## 一、为什么要有素材库

工作流配方负责保存和复现一套工作流；参数笔记本负责记录配方内的参数变化；模型医生负责确认、恢复模型身份。它们都不是“把零散内容挑出来反复使用”的界面。

素材库的职责是提供一个人工整理层：用户从生成图、工作流配方或提示词笔记中挑选值得复用的内容，保存成一个素材包，再按使用场景取出完整工作流或单个节点参数。素材库不能替代原有入口，也不能把模型识别、节点参数应用和素材整理混成一个模块。

## 二、当前 MVP 的真实数据链

```text
主图库或工作流配方图库中的 PNG
  -> 查看详情
  -> 后端读取 PNG 内嵌的 UI workflow
  -> 用户确认或修改默认名称
  -> 保存：原始 PNG + 预览图 + 完整 workflow + 模型引用
  -> 创作工作台 / 素材库
       ├─ 打开完整工作流（整体替换画布）
       └─ 节点助手按 node.type 筛选参数块
            -> 应用到当前节点（忽略种子）
            -> 把源节点 Hash 记录重映射到当前节点
            -> 调用模型医生处理缺失模型
```

只有带 ComfyUI UI 工作流元数据的图片能保存为当前类型的素材快照。只有 API prompt、没有 UI workflow 的图片目前明确拒绝保存，因为它无法可靠恢复画布布局，也无法提供稳定的节点级应用语义。

## 三、一个素材包包含什么

- `kind = image_workflow_snapshot`
- 用户可编辑名称；默认规则为 `主模型 · 提示词摘要 · 日期`
- 生成图的原始 PNG 副本，用作真正的参考图像资产
- 有尺寸上限的 WebP 列表预览
- 图片内嵌的完整 UI workflow，保留精确生成状态和种子
- 从 workflow 动态提取的节点参数块
- 模型引用及 workflow 内已有的 `extra.anomalous_hashes`
- 能力声明：打开完整工作流、应用节点参数、作为参考图像

素材 JSON 与资产位于 ComfyUI 用户目录：

```text
user/<profile>/workflows/anomalous_materials/
  material_<timestamp>_<id>.json
  .assets/<material-stem>/
    source-<sha256>.png
    preview-<sha256>.webp
```

素材数据不得写入插件源码目录。

## 四、必须保持的职责边界

### 素材库

- 保存用户主动挑选的内容。
- 展示、筛选和取出素材。
- 不判断一个模型文件是否是真正的原模型。

### 节点助手

- 按当前选中节点的 `node.type` 筛选可用参数块。
- 事务性写入节点 widget 值。
- 应用单节点素材时跳过种子等运行易变字段。

### 模型医生

- 接管模型路径缺失和模型身份恢复。
- 哈希一致可自动修复；只有大小一致必须等待用户确认；大小与哈希冲突必须拒绝。
- 素材应用只负责携带并重映射已有 Hash 证据，不能自行宣布模型匹配成功。

### 工作流配方与提示词笔记

- 保留原来的直接使用能力，不强制经过素材库。
- 素材库是精选层，不是新的唯一入口。

## 五、保存粒度和默认命名（后续入口使用）

| 来源/选择 | 保存结果 | 默认名称 |
| --- | --- | --- |
| 图片完整快照 | 图片、完整工作流、多个节点块组成一个素材包 | `主模型 · 提示词摘要 · 日期` |
| 配方全部参数 | 一个包含多个块的素材包 | `配方名 · 全部参数` |
| 配方单节点 | 一个节点参数素材 | `配方名 · 节点标题` |
| 配方多选节点 | 一个包含所选块的素材包 | `配方名 · 选中 N 个模块` |
| 提示词笔记完整组合 | 一个组合素材 | `笔记名 · 完整组合` |
| 提示词单块 | 一个提示词素材 | `笔记名 · 正向提示词` 等 |

“保存全部”必须产生一个可管理的组合包，不能把每个节点拆成大量顶层素材。内部块由使用上下文筛选。

## 六、MVP 验收标准

1. 主图库图片悬浮时能看到“查看参数”；配方图库图片悬浮时能看到“查看详情”。
2. 主图库原有的单击放大、拖拽、删除和选择模型封面行为不变；选择封面模式不显示素材入口。
3. 详情为左右栏：左侧图片，右侧默认展示核心摘要、名称和保存按钮。
4. “底层节点详细参数”默认闭合；展开后按节点继续分层展示完整 `widgets_values`、节点属性、模式和易变参数标记。
5. 保存后，素材库出现一张卡片，插件源码目录没有用户数据。
6. “打开完整工作流”使用保存的原始 UI workflow 覆盖当前画布。
7. 选中与素材节点同类型的节点后，节点助手能看到该素材中的对应参数块。
8. 单节点应用不覆盖 KSampler/KSamplerAdvanced 的种子。
9. 源节点的 Hash 证据按目标节点 ID 重映射，随后由模型医生继续处理。
10. 只有 API prompt、损坏元数据、越界路径或超大图片不能进入素材库。
11. 删除素材时同时删除其私有图片资产，不影响原始输出图。

## 七、明确未纳入本次 MVP 的内容

- 从工作流配方参数页按单节点、多选或全部导入素材库。
- 从提示词笔记导入组合或提示词块。
- 把参考图自动复制到 ComfyUI input 并配置 LoadImage 节点。
- 素材标签、文件夹、批量操作、全文搜索和去重合并。
- API-prompt-only 图片到 UI workflow 的推断转换。

以上是后续小步迭代，不得在 UI 重构时伪装成已经存在的功能。

## 八、给 UI 重构者的约束

- 可以重构视觉和布局，但必须保留上述数据链和职责边界。
- 列表接口返回摘要；只有打开或应用时才读取完整 workflow，不能把所有大图和完整图数据塞进列表响应。
- 动态名称、节点标题和提示词必须使用文本节点写入 DOM，不使用不受信任的 `innerHTML`。
- 图库“查看详情”和素材库“打开工作流”是不同动作；查看图片本身仍可保留放大预览。
- 所有用户可见字符串进入 `web/modules/locales.js`。
- 不得仅凭文件名、封面、素材名称或模型大小自动确认模型身份。
